# Playwright test orchestration alternatives

Most teams reach for Playrunner after assembling their own answer to the same
question: _who runs the browser tests, when, on what, and what happens next?_

That question gets answered by three different kinds of product, and they are
not really competing with each other. It is worth being precise about which
one you are actually shopping for.

**Runners run browsers. Playrunner runs the workflow around them — visually,
anywhere.**

## The three categories

|                                                                                                    | What it gives you                                                | What it leaves you to build                                                                                        | Where Playrunner sits                                                                               |
| -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| **CI pipelines** <br /> GitHub Actions, GitLab CI, Jenkins                                         | A place to run a command when something happens in the repo      | Retries, schedules, environment wiring, notifications, ticket creation, artefact routing — all as YAML and scripts | Playrunner takes over the orchestration you piled on top of CI, and CI keeps deciding what can ship |
| **Managed browser grids** <br /> Azure Playwright Workspaces, BrowserStack, LambdaTest, Sauce Labs | Cloud browsers, parallelism, and a report                        | Everything that decides _when_ a run starts and what happens to the result                                         | Playrunner owns the workflow; a grid can still be where the browsers live                           |
| **CI test distribution** <br /> Currents, Sorry Cypress                                            | Faster runs inside the CI you already have, plus flake analytics | Triggers, branching, integrations, runner provisioning                                                             | Playrunner replaces the surrounding glue rather than optimising the run itself                      |

## What Playrunner is not

Being clear about this saves everyone time:

- **Not a test framework.** Playwright is the framework. Playrunner does not
  ask you to rewrite, wrap, or annotate your specs.
- **Not a CI system.** Your pipeline still builds, gates, and deploys.
  Playrunner takes the browser-testing workflow out of it.
- **Not a browser grid.** Playrunner provisions and coordinates runners; it
  does not sell you browser minutes.
